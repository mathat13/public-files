1. A Philosophy of Software Design — John Ousterhout ⭐⭐⭐⭐⭐

This is the one I'd recommend first.

Not because it teaches patterns, but because it teaches how to think about complexity.

The central idea is that good design reduces cognitive load. That should immediately sound familiar.

You'll recognise themes like:

deep modules
information hiding
reducing complexity rather than moving it
designing for understanding
working with stable abstractions

When we talk about extracting a worksheet because a thought log becomes cognitively overloaded, we're dealing with exactly the same forces that Ousterhout describes for software modules.

I suspect you'll spend half the book thinking:

"This applies to reasoning just as much as code."

2. Domain-Driven Design: Tackling Complexity in the Heart of Software ⭐⭐⭐⭐⭐

You've already encountered some DDD.

I think it's worth studying properly.

Not because you need aggregates or repositories, but because Evans is obsessed with:

language,
boundaries,
models,
concepts,
shared understanding.

Those ideas feel very close to what you're building.

I wouldn't focus on the implementation patterns.

I'd focus on:

ubiquitous language
bounded contexts
knowledge crunching
modelling conversations

Those sections feel surprisingly aligned with your methodology.

3. Design Patterns: Elements of Reusable Object-Oriented Software ⭐⭐⭐

Not because you'll use the patterns.

Read it almost anthropologically.

Notice that every pattern exists because somebody repeatedly encountered the same pressure.

That's exactly how your methodology has evolved.

You're already discovering your own "reasoning patterns."

4. Refactoring ⭐⭐⭐⭐⭐

I actually think this one is much more relevant than people realise.

The important lesson isn't:

Rename Method.

It's this:

Structure should improve as understanding improves.

That's almost the defining philosophy of your methodology.

You aren't trying to get the graph right first time.

You're constantly refactoring it.

Likewise with worksheets.

Likewise with questions.
